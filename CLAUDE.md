# openflexito

Thin-device microscope stack. **Rule: the Pi only relays; all image maths lives in `webapp/src/lib/algo` (pure TS, vitest-tested).** The device (`device/openflexito`) exposes data and control only. Never fork the OpenFlexure v3 server; use its sources as an algorithm reference. Licence GPL-3.0-or-later.

## Commands
- device: `cd device && .venv/bin/pytest -q` · run fake: `.venv/bin/python -m openflexito --fake --port 8080`
- webapp: `cd webapp && npm run check && npx vitest --run && npm run build` · dev: `OPENFLEXITO_DEVICE=http://localhost:8080 npm run dev`
- browser e2e (Playwright + installed Chrome): start the fake with `--webapp-dir webapp/dist --port 8099`, then `cd webapp && npm run test:e2e` (44 steps: tabs, jog, link indicator, snapshot, RAW, RAW average, HDR RAW, both calibrations, flat field, drag-to-pan, autofocus, scan (grid, height map, plan-only region changes, corner extent + tab switch + cancel-then-stitch), photo modes, stacks (including the RAW fine stack, whose 16-bit path the 8-bit `focusfine` step cannot cover), live stack, video with stabiliser, measurement, histogram, scan regions, super-resolution JPEG and RAW planes, time-lapse, tracking, sample metadata, macros, settings, logs, WebCodecs video + time-lapse MP4 export, Look/LUT on the live canvas, Enhance panel, live denoise). Run it alone: two suites against one fake drive the same stage and fail erratically. `npm run test:e2e -- http://microscope.local` runs it on the real Pi (moves the stage, rewrites tuning); `E2E_MOVES=0` skips moves. Run it after any UI change: unit tests do not catch Svelte effect loops or leaked MJPEG connections.
- deploy to a running Pi without rebuilding the image: `cd webapp && npm run build && image/deploy.sh` (webapp, device package, network overlay, service restart; `--no-restart` to skip).
- image: `image/build-mac.sh` (mtools injection into the official Bookworm Lite image; needs `image/secrets.env`) is the working builder; `image/build.sh` (sdm) is untested. `sudo image/install.sh [--trim] [--readonly]` on a live Pi.

## Conventions
- The device runs unprivileged with `NoNewPrivileges`; never call sudo. Privileged actions go through `logbuf.request()` (request files handled by `openflexito-maint.path`). Log via `logging` only: the ring handler + persistent journal are what `system.logs` exposes.
- Standby is `device/openflexito/power.py` (`PowerController`): `power.get|set|toggle` RPCs, `power` in `system.status`, camera stopped + illumination remembered-and-zeroed + stage released + LED `off`, image endpoints 503 and camera/stage RPCs refused while off, state persisted in `power.json` so a service restart stays in standby. A future physical button calls the same `device.power.toggle()`. It is not a poweroff — `system.shutdown` still is. Browser side: `components/PowerButton.svelte` + `device.powerOn`/`setPower`/`togglePower`; `App.svelte` swaps the route for a standby screen so nothing streams from a sleeping camera.
- Auto standby: `IdleWatcher` in `power.py` trips the same standby transition after `idle_minutes` (default 10, `0` disables, `power.set_idle`, persisted in `power.json` with `on`/`since`/`reason`). Activity = mutating RPCs (classified at `register_rpc` time via `power.guard(mutating=...)`) + still/raw/bracket fetches + a per-WebSocket `power.activity` heartbeat; an open stream or WS connection counts for nothing, because a background tab's `<img>` keeps streaming. Browser side: `services/activity.svelte.ts` declares the tab active while it is visible, and `activity.hold(reason)` keeps a hidden tab awake for work that makes no RPCs for minutes (recording, live stack, tracking, time-lapse gaps) — hold it in a `finally`, a leaked hold pins the device awake. `reason` (`request`|`idle`) is in `system.status` so a tab opened after the fact can still say why it slept.
- Live page chrome: `routes/Live.svelte` is stream + one-panel drawer + `components/ToolRail.svelte` (`grid: 1fr auto auto`, so a closed drawer gives its width back to the stream). Which tool is open lives in `store/ui.svelte.ts` (`ui.open`/`ui.tool`, persisted to localStorage; first visit closed on desktop, open on `stage` on mobile) plus `ui.immersive` (hides nav/rail/drawer, requests fullscreen, `F`/`Esc`). All drawer panels stay mounted; inactive ones are `div.tool[hidden]`, so the e2e opens a panel with `await tool('Photo')` (the `TOOL_OF` map in `e2e/app.mjs`) before touching it, and a step that spans two panels calls `tool()` again. `components/LiveHud.svelte` overlays the stream with the D-pad/Z/AF buttons (tap = one raw step, hold > 250 ms = continuous jog through the same `JogController` the keyboard uses), position/fps and the immersive toggle; autofocus state shared by the HUD, `FocusPanel.svelte` and the gamepad is `store/focusCtl.svelte.ts`. The rail is an `<aside>`, not a `<nav>`: the e2e reads the position from the single `nav`.
- Mobile: breakpoint `@media (max-width: 720px)` everywhere, coarse-pointer sizing in `@media (pointer: coarse)`, shared `.cols`/`.scroll-x` helpers and `--tabbar-h` (height of the fixed bottom tab bar) in `app.css`; component-local responsive rules live in each component's own `<style>`. Touch gesture maths is `lib/input/zoomPan.ts` (pure, tested); on the live view a long-press replaces shift-drag and multi-touch never drives the stage.
- Anything that touches the camera from another thread (encoder output, picamera2 callbacks) must not iterate shared containers without `_meta_lock`; wrap thread callbacks in try/except, an exception there kills picamera2's thread and freezes the stream silently.
- Files copied onto the Pi must be root-owned: `rsync --chown=root:root`, `tar --uid 0`; NetworkManager ignores profiles that aren't root:root 0600.
- RPC methods are registered in `device/openflexito/app.py` (`register_rpc`); names are `group.verb`; params are keyword JSON. `GET /rpc/schema` is generated from type hints, keep hints accurate.
- Timestamps everywhere are nanoseconds on CLOCK_BOOTTIME (same clock as libcamera `SensorTimestamp`); the browser interpolates z per frame from `event.position` t0/t1.
- Backlash follows v3 `BaseStage` (reference: `things/stage/__init__.py` in openflexure-microscope-server): state starts at 0, `compensate: true` corrects only the moving axes, `"all" | "xy" | "z"` force axes (scans `"xy"`, autofocus final approach `"z"`). Raw moves (jog, drag-to-pan, click-to-centre, sweeps, CSM) pass `compensate: false`. When porting stage/camera behaviour, read the v3 source first and note the divergence in the docstring.
- Live-view pointer model: click-hold-drag pans the stage (`lib/input/pan.ts`, one raw move in flight, image translated by the unmet remainder), plain click centres, shift-drag selects. Anything that needs px→steps requires the CSM calibration.
- Layering: `lib/algo` imports nothing outside `lib/algo` (its types live in `algo/types.ts`, re-exported by `api/types.ts`); services orchestrate algo + api; components and routes never call `fetch` directly, they go through a service or `lib/api` (`api/snapshot.ts` fetches `/snapshot.jpg` and, via `fetchSnapshotWithMeta`, parses a still's own `X-Frame` metadata; `api/raw.ts` fetches `/raw.bin`, `/flat.bin` and `/bracket.bin`; `api/mjpegStream.ts` reads `/stream.mjpg` by `fetch`+`ReadableStream` instead of an `<img>` element, for callers that need every real frame exactly once). Workers use `defineWorker`/`post` from `workers/workerUtil.ts` (errors reach the caller as `{ error }`). Naming: a file is `*.svelte.ts` iff it holds runes (`$state`, `$derived`); stateless services stay plain `.ts`.
- Svelte 5 runes; reactive stores are `*.svelte.ts`. No UI framework; styles in `src/app.css` + component `<style>`. Never write a `$state` you also read inside the same `$effect` (infinite loop that kills the whole app); clear `img.src` of MJPEG images on unmount (a detached `<img>` keeps streaming); never put `$state` proxies into IndexedDB (structured clone fails).
- The fake camera (`--fake`, `device/openflexito/fake_camera.py`) renders a stage-coupled specimen (1 px/step, 4° axis rotation, defocus ∝ |z|), so calibration, autofocus and scans work end to end without hardware.
- Hardware-specific values (UART, IMX219 modes, LED sysfs) are documented in `README.md`; don't change `config-openflexito.txt` without re-checking the Pi 3B+ notes there.
- RAW develop (`algo/rawdev.ts`) applies the tuning file's ALSC tables (or a measured flat field from `algo/flatField.ts`), the record's own colour gains/CCM and gamma; `algo/dng.ts` writes the mosaic as DNG (ColorMatrix1 unbalanced by the white-balance gains, EXIF IFD, GainMap opcodes); `algo/pyramidFuse.ts` is the fine-stack fusion (float planes in, 8- or 16-bit out, noise-floor averaging below a per-level threshold, optional hybrid DMap-confidence blend); focus-stack slices are aligned sub-pixel by `algo/align.ts` (`SliceAligner`: neighbour-chained from the *middle* slice by default, phase correlation at ≤410 px then NCC refinement up to full resolution, Lanczos-3 resampling) in both `stackWorker.ts` and `services/photo/focusStack.ts`. Raw captures are OFRW v2 (`device/openflexito/rawfmt.py`: v1 header + pixels + JSON trailer); `frames=N` averages N frames into a 16-bit mean in one mode switch, `packed=1` is CSI2P 4-in-5, `/flat.bin` is the same endpoint with `flat: true`, `/bracket.bin` is an OFBK container of an exposure bracket; `rawdev.ts`/`rawWorker.ts` must use the record's own trailer values (bit depth, black/white level, gains, CCM), never the live stream's. White balance UI: `services/whiteBalance.svelte.ts` (neutral picker, temperature/tint mapping).
- Live focus stack (`algo/liveStack.ts` in `liveStackWorker.ts`, driven by `services/liveStack.svelte.ts` which grabs frames from the StreamView `<img>`, re-anchoring its alignment reference to the composite every 200 frames) and video recording (`services/recorder.svelte.ts`, a `VideoSink` on a canvas, gallery kind `video`). Anything that needs the live `<img>` reads `liveStack.source`. Recording the plain live view (`Recorder.startStream()`) reads frames through `api/mjpegStream.ts` instead of the `<img>` element (the `<img>` lags its own frame metadata and can be sampled mid-decode); an optional stabiliser (`algo/stabilize.ts`) is skipped and reset whenever `device.moving` is true so a real stage move is never treated as jitter.
- Per-frame processing chain: `services/frameChain.ts` is the one place anything that transforms a decoded frame plugs in (`FrameProcessor` with `order`, `enabled(target)`, `process(frame, target, t)`); targets are `view` (StreamView's `<canvas class="processed">`, fed by a second `api/mjpegStream.ts` client and shown over the ghosted `<img>` only while `frameChain.active('view')`), `record` (the recorder's draw chokepoint) and `playback` (TimelapseViewer). Registered processors: deflicker (50, `services/deflickerProcessor.ts`), live temporal denoise (100, `services/denoiseProcessor.ts`, `algo/temporalDenoise.ts` fed the stage shift via the CSM calibration), look/LUT (900, `services/lookProcessor.ts`). `enabled()` must read only cheap flags, never a per-change object like `look.current`: `frameChain.active()` is read inside effects that start streams. Never edit StreamView or the recorder to add a stage; register one.
- Looks / LUTs: `algo/lut.ts` (parsers for .cube 1D/3D, .3dl text (blue-fastest, re-indexed), ImageJ .lut binary/text, Hald CLUT PNG, CSV ramps; tetrahedral/trilinear sampling; `applyLookRgba`/`applyLookFloat`, `bakeLook`, `toCube`), `algo/curves.ts` (monotone cubic curves, levels, `bakeAdjustments`), `algo/colormaps.ts` (Matplotlib and ImageJ maps generated in code from their published control points, never shipped as binaries). `store/look.svelte.ts` composes LUT + adjustments into one `Look`, persists the selection to localStorage and user LUTs to IndexedDB (`store/lutDb.ts`); `lib/gfx/lutGl.ts` is the WebGL2 `sampler3D` path (the only WebGL in the app), CPU fallback otherwise; `components/LookPanel.svelte` in Live, with `CurveEditor.svelte` (master + RGB curves, maths in `algo/curvePoints.ts`), `GradientEditor.svelte` (colour stops for 1D maps, `algo/gradientStops.ts`), a 3×3 channel mixer, and `look.saveAsLut()` which bakes the whole composed look into a user LUT (1D when channel-separable, else 33³) and resets the adjustments so the picture is unchanged. The look is applied on the live view, baked into recordings when `settings.lookBakeIntoRecording`, shown in the gallery when `settings.lookApplyInGallery` (Viewer re-encodes through `applyLookRgba`), and on time-lapse playback/export.
- Enhance pipeline: `algo/pipeline.ts` `developPipeline(input, EnhanceParams)` runs the canonical order (pseudo-flat-field, vignette, CA, denoise (Anscombe when a `NoiseModel` is known, else MAD sigma), deconvolve via `deconvolve.ts`, filmic, sRGB encode, auto-levels, shadows/highlights, colour, sharpen, CLAHE, look) on `algo/{noise,denoise,enhance}.ts`; `denoise.ts` has wavelet BayesShrink/SURE (default), integral-image NLM (quality tier, ~2.6 s/MP at patch 2 / search 6, keep it opt-in), guided and bilateral filters and a `Denoiser` registry for a future ONNX backend. Driven by `workers/enhanceWorker.ts` (preview at `settings.enhancePreviewWidth`, full-res on Apply) from `services/enhance.svelte.ts` and `components/EnhancePanel.svelte` in the gallery Viewer; "Apply" saves a new item `<name> (enhanced)` with `enhance: { params, source }`. A RAW item's 16-bit `image` blob is display-referred (gamma applied), not linear. Always `$state.snapshot()` params before posting to the worker.
- Video: `services/videoEncoder.ts` (`VideoSink`: WebCodecs `VideoEncoder` through mediabunny (MPL-2.0) into fast-start MP4/WebM with the device frame time as the sample timestamp and a bounded in-flight queue that drops instead of blocking the MJPEG reader; `MediaRecorderSink` fallback whose WebM duration patch only rewrites an existing placeholder, so Chrome's fallback files still show no duration). Never await mediabunny's `getMimeType()` before frames are added (it resolves after the first sample). `services/timelapseExport.ts` + `workers/encodeWorker.ts` encode stored time-lapse frames to MP4 at an exact fps; `algo/deflicker.ts` is the per-frame gain normaliser. Video item meta records encoder, container, codec, quality, dropped/duplicated counts.
- Photos: `services/photoService.ts` only dispatches by mode; the capture code itself lives in `services/photo/*.ts` (`focusStack.ts`, `superres.ts`, `rawPhoto.ts`, `exposureStack.ts`, shared helpers in `common.ts`), one file per mode family so agents/reviewers can own a mode without touching the others. Full-resolution stills (`/snapshot.jpg?full=1`, 1.3 s on the Pi); focus and LED-exposure stacks are merged in the browser by `algo/stack.ts` (per-block weights, smoothed, single blend pass). Extra LEDs go on the Sangaboard's PWM outputs (`light.set {pwm:[..]}`, channel counts in `light.get`), not the Pi GPIO.
- `services/cameraLock.ts` (`lockCamera`/`CameraLock.release`) freezes AE/AWB from the latest frame's metadata for the duration of any multi-shot run (focus stack, LED/exposure stack, super-resolution, scan, time-lapse) and hands control back afterwards; use it instead of a mode inventing its own lock/restore.
- AI features live in `webapp/src/lib/workers/aiWorker.ts` (Transformers.js) + `services/{aiService,searchService,followService}`. Models are Hugging Face ids in Settings; default `Xenova/yolos-tiny` and `Xenova/clip-vit-base-patch32`.
- Scale bar and measurement: `algo/measure.ts` (polygon area/perimeter, angle, µm/px derivation, nice scale-bar length) + `store/scaleCal.svelte.ts` (stage-calibration or manual µm/px, settings `stageStepUm`) + `services/measureService.svelte.ts` (toolbar state, CSV export), rendered by `StreamView.svelte` (live) and `components/Viewer.svelte` (gallery). Histogram and auto-exposure: `algo/histogram.ts` + `components/Histogram.svelte` in the Camera panel.
- Time-lapse (`algo/drift.ts`, `services/timelapse.svelte.ts`, `components/{TimelapsePanel,TimelapseViewer}.svelte`, gallery kind `timelapse`) and organism tracking (`algo/tracking.ts`, `services/tracking.svelte.ts`, `components/TrackingPanel.svelte`) follow the same algo/service/component layering as the rest of Live; tracking overlays trajectories via `StreamView`'s additive `paths` prop.
- The current sample is `store/sample.svelte.ts` (`components/SamplePanel.svelte`, copied onto items in `saveSnapshot`/`saveVideo`); macro recording/replay is `lib/algo/macro.ts` (pure, tested) driven by `services/macro.svelte.ts` (hooks `RpcClient.onCall` in `lib/api/rpc.ts`, storage in `store/macroDb.ts`) via `components/MacroPanel.svelte`.
- Pixel-shift super-resolution (`services/photo/superres.ts`, `algo/drizzle.ts`, `workers/superresWorker.ts`) and depth-from-focus (`algo/depthMap.ts`, fed by `PyramidFuser.depthIndex()` in `algo/pyramidFuse.ts`) for the fine focus stack. `algo/register.ts` (coarse-to-fine registration on top of `algo/fftTrack.ts`'s sub-pixel `displacement()`) is the one registration primitive everything that needs an accurate frame-to-frame shift should use (super-resolution, and anything else measuring sub-pixel motion); don't reinvent whole-frame-downscale-then-correlate elsewhere. Export file names come from `algo/naming.ts` (`fileStem`/`blobFileName`: `YYYYMMDD-HHMMSS_sample_label_x_y_z_blob.ext`), pure and shared by every export path.
- Scan autofocus/height-map maths is `algo/heightMap.ts` (robust plane fit, bilinear sub-grid interpolation, outlier rejection); programmable regions (polygon clipping, spiral order), the two extents (N×M around here, or the grid covering two marked corners: `buildScanPlan`, `gridCovering`) and the stage↔mosaic mapping (`fovRectNorm`) are in `algo/scanPlan.ts`. The run lives in `services/scan.svelte.ts` (`scan` singleton: config persisted to localStorage, frozen plan while running, per-tile states, cancel keeps captured tiles for a stitch-or-discard decision, `activity.hold('scan')`), never in the route; `components/ScanMap.svelte` is the one picture for planning, running and reviewing (tile grid in mosaic space, live view at the stage position, thumbnails as tiles land, polygon editor, the last same-footprint mosaic as underlay); `components/HeightMapOverlay.svelte` shows the result in the Viewer.
